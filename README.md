## Domain assumptions



- **Hong Kong only.** Assuming the application is primarily for HK as the business only sells in HK and following _YAGNI_. So things like phone validation validates for HK
- **One row per clinic.** A doctor with multiple clinics is stored once per
  clinic (name clashes make deduplication unreliable) — no separate clinic table.
- **Public holidays are all-or-nothing.** HK clinics open or close on public
  holidays as a whole, regardless of weekday — so `is_open_on_public_holidays`
  is one flag, not per-day.
- **`place_id` is the Google Places ID** for a clinic, used for navigation.
- **Day of week follows ISO 8601** (1 = Monday, 7 = Sunday) in `operating_hours`.
- **Column-based translations.** Translatable fields are fixed `en`/`yue`/`zh`
  columns. HK has three relevant languages,
  so the set is closed — a translation table would add joins for no gain, and a
  TMS (Lokalise/Crowdin) is for developer-owned UI strings, not user-generated
  content: practitioner data arrives via the API at runtime, so a TMS would mean
  writing each record twice (API + catalog). A TMS would only help for static
  error strings, which this API has none of.

## Framework and library choices

- **FastAPI** — minimal compared to Django; typed, validated, automatic OpenAPI
  documentation, and async is first-class.
- **SQLModel + SQLAlchemy** — ORM models double as typed tables, so the schema
  and ORM share one type system end to end.
- **Pydantic** — first-class support in FastAPI; it enforces and validates the
  request/response structure at the boundary.
- **Jetbase** — plain-SQL migrations with an `upgrade`/`rollback` split, so the
  schema stays a readable spec rather than ORM-autogenerated diffs.
- **phonenumbers** — (implementation of `libphonenumber`), phone validation
  covers a wide range of formats as it's actively updated,
  rather than a hand-rolled regex.
- **Postgres + Redis** — no specific reason for choosing Postgres over MariaDB or MySQL. Redis for cache: if we
  deploy multiple app instances, they share the same cache rather than each
  holding its own.

## Potential improvements

In rough priority order:

- **Idempotency on create** — `POST /doctor[/batch]` are not idempotent; an
  `Idempotency-Key` header (claim in Redis, replay the stored response) would
  make retries safe.
- **PUT/PATCH/DELETE** — no way to update/delete a doctor yet.
- **Auth** - POST endpoints should be authorized so only admins can create doctors
- **Real Mandarin content** — `*_zh` is seeded as a copy of the Cantonese text.
- **Search** — filtering is exact-match; name search would need full-text
  indexes (e.g. Elasticsearch).
- **Plural endpoints**: Left endpoint to `doctor` instead of `doctors`. Using singular instead of standard REST API which should use plurals for all other APIs, in order to standardize across all endpoints.

## Production considerations

- **Secrets** — `.env` is local-only; production should use something like AWS secrets manager.
- **Migrations as a deploy step** — run `jetbase upgrade` before rollout
  (initContainer / migration job), not in the app, so replicas don't race.
- **Cache invalidation** — catalogs + response cache share a TTL; seed changes
  take effect on expiry, so runtime reference-data edits need a cache clear. Generally we can use a flush endpoint for clearing cache
- **Connection management** — per-process engine/Redis; pool sizing needs to be
  deliberate behind multiple ASGI workers.
- **Observability** — add OpenTelemetry for traces/metrics/logs. It integrates
  with AWS X-Ray for tracing and Prometheus/Grafana for metrics.
- **Boundary validation** — schema constraints return 422, never a 500 from the
  DB; that contract should hold as the schema evolves.

## Run and build

### 1. Local development (deps in Docker, app on host)

```bash
# one-time setup
python -m venv .venv
source .venv/bin/activate
pip install -e ".[dev]"

# every session
docker compose up -d                                   # postgres + redis
(cd jetbase && ../.venv/bin/jetbase upgrade)           # apply migrations
.venv/bin/uvicorn necktie.main:app --reload            # app on :8000
```

Docs at http://localhost:8000/docs.

### 2. Full stack in Docker

Builds and runs the exact artifact CI produces:

```bash
./scripts/local.sh
# or: docker compose -f docker-compose.yml -f docker-compose.local.yml up --build -d
```

App on `http://localhost:${APP_PORT:-8000}`. To run a pre-built GHCR image
instead of building from source, set `DOCKER_IMAGE=ghcr.io/gnumilanix/necktie:latest`.

### 3. Tests and verification

```bash
docker compose up -d && .venv/bin/pytest               # tests (needs deps)
./scripts/verify.sh                                    # full local CI
```

### Scripts

| Script | What it does |
|---|---|
| `scripts/local.sh` | Build and run the full stack in Docker |
| `scripts/build.sh` | Build the Docker image (`necktie:local` or a tag arg) |
| `scripts/verify.sh` | Lint + mypy + bandit + pytest + Docker build |
| `scripts/teardown.sh` | Stop containers, drop volumes, free the port, wipe venv/caches |

### `POST /doctor`

Create one doctor. `name` and `address` require all three languages;
`fee_detail` is optional per language. Phone numbers are validated (HK region).

```
POST /doctor
Content-Type: application/json
```

<details>
<summary>Sample payload</summary>

```json
{
  "category_id": 19,
  "district_id": 1,
  "consultation_fee": 300,
  "phone_numbers": ["23456789"],
  "name": { "en": "Dr Test", "yue": "測試醫生", "zh": "测试医生" },
  "address": { "en": "1 Test St", "yue": "測試街1號", "zh": "测试街1号" },
  "fee_detail": { "en": "Mon–Fri" },
  "operating_hours": [
    { "day_of_week": 1, "open_time": "09:00", "close_time": "18:00" }
  ]
}
```

</details>

Returns 201 with the created doctor (localized, default language). 400 if
`category_id`/`district_id` is invalid; 422 if required fields are missing.

### `POST /doctor/batch`

Create many doctors in one transaction. Body is a JSON array of the same
`POST /doctor` payload. Returns 201 with the created list.

### Errors

| Status | When |
|---|---|
| 400 | Invalid `category_id` / `district_id` on create |
| 404 | `GET /doctor/{id}` with an unknown id |
| 422 | Validation failure (missing required field, bad phone number, unknown `language`) |
